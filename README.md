# 历史记录 WebDAV 同步

一个无需服务器的 Chrome Manifest V3 扩展。它会监听 Chrome 历史记录，保存页面访问时间；页面在前台时也会记录停留时长。数据按本地日期分别储存，并同步为 WebDAV 目录中的 `YYYY-MM-DD.json`。

## 安装

1. 在 Chrome 打开 `chrome://extensions`，打开“开发者模式”。
2. 选择“加载已解压的扩展程序”，选择本项目目录。
3. 点击扩展图标，进入“设置 WebDAV”，填入 WebDAV 根地址、凭据和可选目录。

例如，地址是 `https://dav.example.com/remote.php/dav/files/alice`、目录是 `chrome-history` 时，文件会上传到 `…/alice/chrome-history/2026-08-25.json`。WebDAV 服务需要支持 `GET` 和 `PUT`；请使用 HTTPS 和应用专用密码。

## 同步规则

- 默认导入并同步最近 7 天，可在设置修改。
- 每个日期对应一个 JSON 文件，记录 `url`、`title`、`visitTime`（毫秒时间戳）和 `duration`（前台停留毫秒）。
- 点击扩展图标会直接打开历史页，页面提供上传、下载和设置按钮。上传前会拉取远端同日数据并合并，以免覆盖另一台设备的新增记录。
- 历史页按日期分页面显示，可选日期、前后翻页及快速选择最近日期；当天连续访问同一网站会自动折叠。页面展示真实访问时间、URL 和停留时长，并适配手机窄屏。
- 默认在查看没有本地记录的日期时自动下载该日期远端文件，此行为可在设置关闭。将记录导入 Chrome 原生历史也是可选项，且默认关闭。Chrome 的公开扩展 API 不允许指定历史条目的原始访问时间，因此原生历史界面中的导入条目会显示为导入时刻。
- 可在设置中给每台设备指定设备标识；新上传的记录带有来源标识，历史页会以云朵图标标记其他设备产生的记录。日期快捷栏可固定在页面顶部或底部。
- 每次上传（包括自动同步中的上传阶段）前，会从 Chrome 原生历史补齐配置天数内的访问记录。

## 可选端到端加密

在设置中填写“数据加密密码”后，每个文件会以 AES-256-GCM 加密，并使用 PBKDF2-SHA-256（250,000 次迭代）从密码派生密钥。WebDAV 服务只会看到盐值、随机向量和密文；所有设备必须使用相同密码。请保管好该密码，遗失后无法解密已有文件。仍建议使用 HTTPS，以保护 WebDAV 登录凭据和传输元数据。

## 项目结构

这是一个原生 Chrome 扩展，没有构建步骤或第三方运行时依赖。主要文件如下：

| 文件 | 职责 |
| --- | --- |
| `manifest.json` | Manifest V3 配置、权限、后台入口和设置页入口。 |
| `background.js` | 记录访问与停留时长；维护本地记录；处理 WebDAV 上传、下载、合并、配置同步和可选加密；响应页面消息并安排定时同步。 |
| `history6.html` | 历史记录页面的 HTML 结构及样式、脚本入口。 |
| `history2.js` | 历史日期和记录展示、搜索、分页、上传与下载交互。 |
| `history5extra.js`、`history6extra.js` | 历史页的存储信息和窄屏搜索交互补充。 |
| `options3.html`、`options3.js` | WebDAV、加密、同步、浏览和主题设置，以及设备配对。 |
| `theme.js`、`theme-extra.js` | 历史页和设置页共用的主题应用逻辑。 |
| `style.css`、`theme-overrides.css`、`effects*.css`、`layout*.css`、`mobile*.css`、`options2.css`、`textarea-theme.css` | 页面基础样式、主题效果、布局、移动端适配和设置页样式。 |
| `icon/` | 扩展工具栏和管理页面使用的图标。 |

## 数据与同步流程

- 本地历史保存在 `chrome.storage.local`，按本地日期使用 `history:YYYY-MM-DD` 作为存储键。单条记录包含 URL、标题、访问时间戳、前台停留毫秒数和设备标识。
- 后台通过 Chrome History、Tabs、Windows 和 Idle API 记录访问；页面进入前台时开始计时，离开或浏览器空闲时结束计时。相同 URL 和访问时间的记录会合并，停留时长取较大值。
- WebDAV 中每天对应一个 `YYYY-MM-DD.json` 文件；可同步的设置保存在同目录的 `user.config.json`。加密开启时，这些文件都会加密。
- 下载会把远端数据与本地数据合并；上传前会补齐 Chrome 原生历史、读取远端同日数据并合并后再写回，降低多设备互相覆盖的风险。自动同步按设置的间隔先下载再上传。
- 历史页通过 `chrome.runtime.sendMessage` 向后台请求历史数据和同步操作；设置页直接使用 `chrome.storage.local` 保存设置。WebDAV 请求由后台处理。

## 本地开发

1. 在 Chrome 打开 `chrome://extensions` 并开启“开发者模式”。
2. 选择“加载已解压的扩展程序”，加载项目根目录。
3. 修改代码后，在扩展管理页点击刷新图标；需要排查后台问题时，打开扩展的 Service Worker 检查器查看控制台。
4. 在扩展页面验证历史展示、设置保存以及 WebDAV 上传和下载。同步测试需要可访问的 WebDAV 服务；开启加密时，测试设备需配置相同的加密密码。

## 权限说明

- `history`：读取 Chrome 原生访问记录，并按用户选项导入同步记录。
- `storage`：保存本地访问记录、配置和会话中的计时状态。
- `tabs`：跟踪当前前台标签页及其导航，用于记录访问和停留时长。
- `alarms`：按设置的间隔触发自动同步。
- `idle`：用户离开设备时结束前台停留计时。
- `http://*/*`、`https://*/*` 主机权限：允许扩展连接用户自行配置的 WebDAV 服务地址。建议仅使用 HTTPS。
